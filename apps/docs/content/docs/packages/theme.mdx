One theme lives as a VS Code color theme JSON. `magic-theme install` reads it and writes the
matching file for every editor and terminal it finds on the machine, so a palette change is one
edit and one command instead of six hand-maintained config files drifting apart.

## Install

```sh
pnpm add -D magic-theme
pnpm exec magic-theme install
```

With no arguments, `install` writes every target it detects. Pass names to limit the run:

```sh
pnpm exec magic-theme install cursor warp
```

`uninstall` removes everything it wrote, and `path <target>` prints where a target's file lands
without touching it.

theme, not a re-picked copy.

## Targets

| Target          | What it gets                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| Cursor, VS Code | An extension. Pick "Magic Theme" in the color theme picker.                                           |
| Warp, Orca      | A theme file. Pick it in the app's Themes UI.                                                         |
| Ghostty         | A theme file. Set `theme = magic-theme` in its config.                                                |
| Alacritty       | A generated toml. Add `import = ["~/.config/alacritty/themes/magic-theme.toml"]` to `alacritty.toml`. |

Edit the VS Code theme JSON, re-run `install`, and every target follows.
