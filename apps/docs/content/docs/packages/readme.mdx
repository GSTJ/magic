`magic-readme init` writes the standard's skeleton into a directory: hero, tagline, badges, `##
How it works`, `## Install`, then package detail sections. `magic-readme check` runs seven
mechanical rules over any README and exits non-zero listing what is off, with a line number for
each:

```
$ magic-readme check README.md
README.md
  - no tagline: a <p align="center"> block with plain text and no image must come before the first heading.
  - no `## Install` heading.

magic-readme: 2 problem(s).
```

`pnpm run check` in this repo runs that same validator over every package README plus the root
one, so a README can't drift from the standard without failing CI.

## Install

```sh
npm install --save-dev magic-readmes
```

Or run it once without installing: `npx magic-readmes init`. The package is `magic-readmes`; the
command it installs is `magic-readme`.

## Rules

`check` enforces the structure a machine can judge honestly. Prose quality, a hype tagline or a
useless mechanism list, stays a human concern in review.

| Rule                    | What fails                                                                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Hero                    | No `<p align="center">` block holding an `<img>` with an absolute https `src`, before the first heading.                                               |
| Tagline                 | No centered plain-text block, no image, before the first heading.                                                                                      |
| npm badge               | No shieldcn.dev npm version badge pointing at the package's own name from the adjacent `package.json`. Private packages and loose files skip this one. |
| `## Install`            | Heading missing.                                                                                                                                       |
| Em and en dashes        | Found outside a fenced code block.                                                                                                                     |
| Relative image `src`    | Any markdown or HTML image path that isn't absolute. npm renders READMEs away from the repo, so a relative path 404s on the package page.              |
| Pinned install versions | An exact `name@x.y.z` inside a fenced code block. Moving tags and ranges pass.                                                                         |

## Media

Hero images come from one pipeline: `magic-video` renders every package's hero still and demo
clip into the repo root `media/` directory, which is committed. READMEs then point at the raw
GitHub URL, in the shape
`https://assets.gabrieltaveira.dev/magic/magic-readme.png`, so the same file
renders on GitHub and on npm.
